# 大厂裁员生存模拟器 可玩原型设计

## Decision

首轮采用“可玩原型优先”。目标不是一次性完成 200 条事件和完整商业化配置，而是先做一个能完整跑通的网页文字生存游戏：

- 玩家可以开始一局 90 天裁员潮。
- 每天有 3 点精力，可在 5 类行动中分配。
- 4 项核心数值和 1 项隐藏数值会随行动与事件变化。
- 任意核心数值归零会 Game Over。
- Game Over 支持一次模拟激励广告复活。
- 一局结束可以进入多结局判定。
- 事件、行动、结局、广告点位都通过配置驱动，后续可以扩展到 200 条事件与 Excel 数值表。

## Product Positioning

《大厂裁员生存模拟器》是职场情绪向文字生存游戏。它面向互联网、白领和泛职场用户，主打情绪宣泄、反鸡汤、强共鸣和社交传播。

首版体验重点：

- 每个选择都能让玩家感到“懂我”。
- 数值变化清晰，避免玩家觉得自己被随机惩罚。
- 文案高密度植入互联网黑话，但不影响理解。
- 广告点位以“救命”“少受苦”“提前知道”为核心，不打断正常回合节奏。

## Core Loop

一局游戏为 90 天。

每天流程：

1. 显示当天公司状态与玩家状态。
2. 玩家分配 3 点精力到 5 类行动。
3. 行动立即改变核心数值。
4. 系统抽取一个随机事件。
5. 玩家选择事件选项，事件至少影响 2 项数值。
6. 结算埋雷指数、归零失败、阶段事件和结局条件。
7. 进入下一天。

每 30 天进入一次裁员潮节点。第 90 天根据最终状态判定结局。

## Player Actions

行动类型固定为 5 类：

- 加班干活：绩效分增加，发量值减少，埋雷指数小幅下降。
- 摸鱼划水：发量值和尊严值增加，绩效分减少。
- 向上管理：绩效分增加，尊严值减少，埋雷指数可能增加。
- 抱团站队：尊严值小幅减少，埋雷指数降低或转移，可能触发关系类事件。
- 副业赚钱：存款额增加，发量值减少，绩效分小幅减少。

首版每次点击行动消耗 1 点精力。每天精力用完后才能进入事件结算。

## Stats

核心数值：

| Stat | Initial | Max | Failure |
|---|---:|---:|---|
| performance | 60 | 100 | 绩效不达标被裁员 |
| hair | 80 | 100 | 身体垮掉主动离职 |
| dignity | 70 | 100 | 心态崩溃裸辞 |
| savings | 5000 | none | 交不起房租被迫回老家 |

隐藏数值：

- landmine：埋雷指数，初始值 10，上限 100。
- 当 landmine 达到 80 以上时，事件和每日结算会提高危机事件权重。
- 当 landmine 爆发时，直接扣大量绩效和尊严，并重置一部分 landmine。

数值边界：

- performance、hair、dignity 固定在 0-100。
- savings 无上限，但低于或等于 0 触发失败。
- 所有事件至少改变 2 项数值或 1 项核心数值加 landmine。

## Event System

首版配置事件数量为 30 条左右，用于验证循环：

- daily：约 70%，轻度波动，2 个选项。
- crisis：约 20%，高强度冲击，3 个选项。
- opportunity：约 10%，正向跃迁或高风险高收益，2-3 个选项。

事件 JSON 字段：

- id
- type
- title
- body
- weight
- minDay
- maxDay
- condition
- choices
- choice.label
- choice.effects
- choice.feedback
- choice.tags

后续扩展到 200 条事件时保持同一结构，不改前端解析逻辑。

## Ending System

首版实现 6 个结局，配置预留到 12 个：

- 试用期被优化
- 身体垮掉主动离职
- 心态崩溃裸辞
- 交不起房租被迫回老家
- 撑到年底拿年终奖
- 反向晋升为管理层

判定优先级：

1. 归零失败结局。
2. 第 90 天特殊胜利结局。
3. 普通生存结局。

## Monetization Hooks

首版不接真实广告 SDK，只实现模拟激励广告接口和 UI 点位：

- deathRevive：Game Over 后看广告复活一次，恢复 50% 全核心数值。
- dailyBuff：开局看广告获得“今日摸鱼不被抓”，当天摸鱼不扣绩效。
- talentUnlock：看广告解锁初始天赋，首版先做按钮占位。
- endingPreview：看广告预览隐藏结局条件，首版先做按钮占位。
- skipCrisis：危机事件时看广告跳过负面事件，首版可用一次。

广告接口设计为异步函数，未来可替换真实 SDK。

## Architecture

采用轻量网页原型：

- index.html：页面入口。
- src/main.ts：挂载游戏。
- src/game/state.ts：游戏状态模型。
- src/game/actions.ts：行动结算。
- src/game/events.ts：事件抽取与事件效果应用。
- src/game/endings.ts：结局判定。
- src/game/ads.ts：模拟激励广告接口。
- src/data/events.ts：首批事件配置。
- src/data/endings.ts：结局配置。
- src/styles.css：界面样式。

为了避免首版被构建工具和安装依赖阻塞，可先做原生 HTML/CSS/TypeScript 或 JavaScript。若本地 Node 依赖可用，再升级 Vite + TypeScript。

## UI

首屏直接是游戏，不做营销落地页。

主要区域：

- 顶部状态栏：天数、绩效、发量、尊严、存款。
- 中间公司播报/事件卡。
- 行动区：5 个行动按钮，显示消耗和影响倾向。
- 事件选择区：显示事件选项和数值变化预览。
- 底部日志：记录最近 5 条反馈。
- Game Over / Ending 弹窗：显示原因、广告复活、重新开始。

移动端优先：

- 按钮高度不低于 44px。
- 状态栏在窄屏下变为两列网格。
- 事件文案区域可滚动。
- 所有交互都不依赖 hover。

## Testing And Verification

首版最低验证：

- 能打开页面。
- 开始/重开游戏正常。
- 每天 3 点精力限制生效。
- 行动会改变数值。
- 事件选项会改变至少 2 项数值。
- 任意核心数值归零触发 Game Over。
- 广告复活只能使用 1 次。
- 第 90 天能进入结局。

若有 Node 环境：

- 增加核心逻辑单元测试。
- 增加浏览器冒烟测试。

## Out Of Scope For First Prototype

首版不做：

- 真实广告 SDK 接入。
- 完整 200 条事件。
- Excel 自动导出全量数值表。
- 用户账号、排行榜、云存档。
- 复杂 NPC 关系网。
- 真实支付或内购。

这些内容通过配置结构预留，放入后续里程碑。
